# 访谈稿匿名化映射编辑器

在浏览器中对访谈稿进行匿名化：维护人物代号与称呼映射，自动识别称呼命中，支持鼠标框选显式指派与批量同文片段指派，可把个别称呼命中标为「保留原文」例外，并可将一位人物合并进另一位（称呼去重、框选与例外一并迁移，整次合并可原子撤销）。当**同一称呼登记在多位人物名下**时，侧栏「共享称呼裁决」会列出冲突称呼、候选人物与原稿命中数；**未裁决的共享称呼不参与自动替换**（不再由人物列表顺序暗中决定代号），用户可为每个冲突称呼选定唯一归属，选定后其自动命中按既有最长称呼、框选与保留例外优先级进入匿名预览，巡检状态与引文随之重算；人物删除或合并导致候选集合变化时，失效裁决自动清除、冲突消失则恢复唯一归属，裁决本身也可用撤销入口恢复。内置**敏感信息巡检**：离线识别原稿中的手机号、邮箱与 18 位身份证号（身份证校验出生日期与校验位），依据最终匿名映射实时判定每个候选为「已匿名 / 保留原文 / 仍泄漏」，可一键把仍泄漏项指派给已有人物。框选弹窗还可**加入引文**：只保存原稿非空半开区间（UTF-16 计数），引文正文依据最终映射实时生成（替换段输出完整代号、其余截取区间内原文），按添加顺序维护可删除的引文列表，可一键下载空行分隔的 UTF-8 TXT。内置**人工复核与交付**：编辑区按原稿区间列出当前最终映射中的全部替换段（原文、代号、来源、待复核/已通过状态），审校者逐条确认，确认记录绑定原稿半开区间、人物 ID 与实际代号文本；规则、框选、例外、共享称呼裁决或人物合并变化后清单自动重建——完全相同的替换保留确认，新增或输出变化的回到待复核，消失的移除；仅当当前替换均已通过且巡检无「仍泄漏」项时方可下载按当前匿名预览生成的 UTF-8 交付稿（界面实时显示未通过与仍泄漏数量），重新加载原稿即清空全部确认。支持**本地工作包**：一键把当前工作（原稿、人物规则、框选、保留例外、共享称呼裁决、引文与复核确认）下载为 `version=1` 的 JSON 文件，并可从该文件导入、校验通过后一次性恢复全部工作（不含预览、巡检结果与撤销栈，均由引擎重算）。所有结果仅体现在匿名预览中，原稿永不改动，并维护原稿 ↔ 预览的双向字符区间映射。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后在浏览器访问：**http://localhost:3000**

入口即首页：粘贴访谈稿点击「加载原稿，开始匿名化」，或点击顶部「加载内置示例」（示例稿内含一处手机号、一处邮箱与一处合法身份证号，并预置了一个两位人物共有的冲突称呼「老师」，可直接体验共享称呼裁决与敏感信息巡检）。

> 端口固定为 `3000`（`docker-compose.yml` 中映射 `"3000:3000"`）。停止服务：`Ctrl+C`；后台运行：`docker compose up --build -d`。

不使用 Docker 时也可直接运行（需 Node.js 18+）：

```bash
npm install
npm start
# 访问 http://localhost:3000
```

## 操作说明

1. **粘贴原稿**：首页文本框粘贴访谈稿，点击「加载原稿，开始匿名化」；或点击顶部「加载内置示例」快速体验。
2. **维护人物规则**：在右侧填写「统一代号 + 称呼（多个用逗号分隔）」并添加人物。自动识别遵循**最长称呼优先**（长度相同则先出现者优先）。
3. **共享称呼裁决**（侧栏「共享称呼裁决」）：当同一称呼（如「老师」）同时登记在多位人物名下时：
   - 侧栏逐条列出**冲突称呼、候选人物与原稿命中数**，未裁决的称呼标记为「未裁决·不替换」；
   - **未裁决的共享称呼不产生任何自动命中**（其原文照录，可被敏感信息巡检判为泄漏），绝不会再由人物列表顺序暗中决定代号；
   - 点击候选人物代号即可把该称呼裁决给该人物，其全部自动命中随即按**最长称呼、显式框选、保留原文例外**的既有优先级进入匿名预览与双向区间映射，**巡检状态与引文实时重算**；
   - 已裁决的称呼点击其标签可在原稿 / 预览中定位首个自动命中；
   - 人物**删除或合并**使候选集合变化时，**失效裁决自动清除**；冲突因合并 / 撤销而消失（称呼只属于一位人物）时，自动**恢复唯一归属**，无需再裁决；
   - 裁决（及改判）作为一条记录进入撤销栈，点顶部「撤销最近操作」即可恢复到操作前的裁决集合。
4. **显式框选（最高优先级）**：在原稿中用鼠标框选任意片段，在弹窗中指派给已有或新建人物。框选可覆盖、切开任何称呼命中与保留原文例外。
5. **批量同文片段指派**：框选非空片段后，在弹窗中选好目标人物（含新建人物），点击「批量指派全文相同片段…」。确认弹窗按原稿**从左到右、互不重叠**地匹配全文完全相同的片段，并分类显示三档数量（互斥，合计为匹配总数）：
   - **可处理**：将新增为显式框选；
   - **与既有显式框选冲突**：跳过（同一匹配同时与框选、例外冲突时，按框选优先归入此类）；
   - **与保留原文例外冲突**：跳过。

   确认后**只新增可处理项**，冲突匹配一律跳过、不覆盖原有区间（与称呼命中的重叠不算冲突，因显式框选优先级更高）；整批变更（含随批量新建的人物）作为**一条撤销记录**，撤销即恢复操作前的区间集合与匿名预览。新增区间与手动框选完全等同，照常参与优先级裁决、双向映射、统计与映射表。
6. **保留原文例外**：
   - 在底部「字符区间映射表」中，对任一**称呼命中**行点击「保留原文」，该处即成为例外：预览中原样照录，并屏蔽与该区间重叠的所有自动称呼命中；
   - 右侧「保留原文例外」列表展示每个例外的**原稿片段**与**来源人物**（点击片段可在原稿/预览中定位）；
   - 点击例外列表或映射表中的「恢复匿名」即可删除例外、恢复自动匿名；
   - 若某例外被显式框选**完全覆盖**，列表中会置灰标注（被部分覆盖时，未覆盖部分仍然保留原文）。
7. **合并人物**：在人物列表中点击目标人物上的「合并」，在弹窗中选择要并入的**源人物**。弹窗会列出双方代号、去重后的称呼，以及将迁移的框选与保留原文例外数量；确认后源人物的称呼（去重）、框选与例外统一改绑到目标人物，源人物删除，重叠称呼仍按**最长称呼优先**处理；与源人物有关的共享称呼裁决随之重算（失效清除、冲突消失恢复唯一归属），整次操作可原子撤销。
8. **双向高亮**：点击或悬停原稿/预览中的高亮片段，可在两侧及映射表间联动定位；点击映射表行同样定位。
9. **敏感信息巡检**（侧栏「敏感信息巡检」）：
   - 加载原稿后**离线**扫描（无任何网络请求）手机号（`1[3-9]` 开头 11 位、两侧非数字）、邮箱与 18 位身份证号；身份证须同时通过**出生日期合法性**（公历、含闰年）与 **ISO 7064 末位校验码**；重叠候选按 **身份证号 ＞ 邮箱 ＞ 手机号、同类更长优先（长度相同取先出现者）** 去重；
   - 依据最终匿名映射把候选判为：**已匿名**（每个字符都被替换映射覆盖）、**保留原文**（无泄漏但落在「保留原文」例外中）、**仍泄漏**（存在照录进预览的字符，并列出泄漏子区间）；
   - 规则、框选、例外、**共享称呼裁决**与人物合并等任何变化后状态**实时重算**；原稿/预览中以红 / 黄 / 绿下划线标记候选；
   - 侧栏可按状态筛选（全部 / 仍泄漏 / 保留原文 / 已匿名，含数量徽标），每条显示片段与**原稿区间**，点击即在原稿与预览中联动定位（悬停同样跨侧联动）；
   - 对单个**仍泄漏**项，可在条目内选择已有人物后点击「指派给人物」：按泄漏子区间补显式框选（已被既有框选覆盖的子区间不重复添加），复用显式框选优先级与**撤销栈**（整次指派一条记录）；指派后候选自动转判「已匿名」。
10. **撤销**：顶部「撤销最近操作」按时间倒序撤销，涵盖添加人物、显式框选、**批量同文指派（整批一条记录）**、**标记例外、恢复匿名、删除人物、合并人物、共享称呼裁决、巡检指派**（删除人物会连同其框选、例外与裁决一并恢复；合并作为一次原子操作撤销，源人物按原 ID、原列表位置、原称呼、全部关联区间及裁决精确恢复；批量指派撤销时整批新增区间一并移除，随批量新建的人物也一并消失）。
11. **引文**：在原稿框选任意非空片段后，在弹窗点「**加入引文**」，即把该片段的原稿半开区间 `[start, end)`（偏移按 **UTF-16 码元**计数，与框选/映射一致）追加到引文列表；引文与是否指派人物无关。
    - 引文正文依据 `public/anonymize.js` 的**最终映射**实时生成：未替换段与「保留原文」段只截取落在区间内的原文字符；只要与某个**替换段**（显式框选或称呼命中）有交集——即使引文边界落在该段内部——就输出**一次完整代号**（如 `【受访者A】`），绝不带入区间外的原文；
    - 多条引文**各自独立计算、允许相互重叠**；人物规则、框选、例外、**裁决**、合并与撤销等任何变化后引文随预览**实时重算**；**重新加载（重新粘贴）原稿时清空全部引文**；
    - 底部「引文列表」按**添加顺序**展示序号、原稿区间与当前引文正文，每条可单独「删除」（删除不影响人物规则、框选与例外），点击正文可在原稿/预览中定位；
    - 「下载引文 TXT」导出 **UTF-8** 编码的 `citations.txt`：按列表顺序排列，条目之间用**一个空行**分隔，文件中**只含引文正文**（无序号、无区间标注）。
12. **人工复核与交付**（底部「人工复核与交付」）：
    - 清单按**原稿区间**列出当前最终映射中的全部**替换段**（显式框选与称呼命中），每条展示**原文、代号、来源**与**待复核 / 已通过**状态，点击原文可在原稿 / 预览中定位该替换段；
    - 审校者逐条点击「确认」；**确认记录绑定原稿半开区间、人物 ID 与实际代号文本**，已通过的条目可「退回」待复核；
    - 规则、框选、例外、**共享称呼裁决**或人物合并等任何变化后清单**自动重建**：完全相同的替换**保留确认**，新增或输出（归属人物 / 代号文本）变化的替换**回到待复核**，消失的替换**移除**（其确认一并丢弃）；
    - **仅当当前替换均已通过且敏感信息巡检无「仍泄漏」项时**，「下载交付稿」按钮启用：按**当前匿名预览**生成 **UTF-8** 编码的 `delivery.txt`；复核栏实时显示**未通过**与**仍泄漏**数量（未满足条件时按钮悬停可见差多少）；
    - **重新加载（重新粘贴）原稿时清空全部复核确认**。
13. **复制结果**：点击「复制匿名预览」复制匿名后的完整文本。
14. **本地工作包（下载 / 导入）**：
    - 顶部「**下载工作包**」把当前工作保存为 UTF-8 编码的 `work-package.json`（`version=1`）：含**原稿、人物规则、框选、保留例外、共享称呼裁决、引文与复核确认**；**不保存**匿名预览、敏感信息巡检结果与撤销栈（均可由保存内容重算）；
    - 顶部「**导入工作包**」选择本地 JSON 文件并**替换当前工作**：先整体校验（版本、字段类型、各集合 ID 唯一性、人物引用、裁决是否属于对应共享称呼的候选人物、所有区间是否为原稿 UTF-16 范围内的非空整数半开区间），**任一错误都按具体字段路径逐条提示**（如 `selections[2].end`、`rulings["老师"]`），且**当前工作保持不变**；
    - 校验通过后**一次性恢复**：复用匿名化引擎按恢复内容重算匿名预览与敏感信息巡检；**复核确认仅当原稿区间、人物 ID 与实际代号均与当前替换完全匹配时保留，其余丢弃**；**撤销栈清空**；继续新增人物或区间时**不复用文件中已有的 ID**（内部编号从各集合最大 ID 之后继续）；
    - 文件读写全部在浏览器本地完成（Blob 下载 / FileReader 读取），不经过服务器；字段格式见下文「本地工作包文件格式」。
15. **重新粘贴**：点击「重新粘贴原稿」可清空全部规则、框选、例外、**共享称呼裁决**、引文、**复核确认**与巡检结果后重新开始。

底部统计与映射表会随以上任何操作实时重算（人物数、框选 / 称呼 / 保留原文处数、被框选完全覆盖的例外数、**冲突称呼数（含未裁决数）**，以及敏感信息三态计数）；人工复核清单、未通过 / 仍泄漏计数与「下载交付稿」启用状态同样实时重算。

## 本地工作包文件格式（version = 1）

「下载工作包」生成的 `work-package.json` 为 UTF-8 编码的 JSON 对象，字段全部必填（未列出的字段会被忽略，便于前向兼容）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number | 工作包格式版本，固定为 `1` |
| `text` | string | 原稿全文 |
| `persons` | array | 人物规则，每项 `{ "id": 整数, "codename": "统一代号", "aliases": ["称呼", …] }` |
| `selections` | array | 显式框选，每项 `{ "id": 整数, "start": 整数, "end": 整数, "personId": 整数 }` |
| `exceptions` | array | 保留原文例外，每项 `{ "id": 整数, "start": 整数, "end": 整数, "personId": 整数 }` |
| `rulings` | object | 共享称呼裁决，`{ "共享称呼": 归属人物ID }` |
| `citations` | array | 引文，每项 `{ "id": 整数, "start": 整数, "end": 整数 }` |
| `reviewApprovals` | array | 复核确认，每项 `{ "start": 整数, "end": 整数, "personId": 整数, "codename": "确认时的实际代号" }` |

约定：

- 所有 `start` / `end` 均为原稿的 **UTF-16 码元偏移**（与编辑器内框选 / 映射表计数一致），必须满足 `0 <= start < end <= text 长度` 的**非空半开区间**；
- 各集合（`persons` / `selections` / `exceptions` / `citations`）内的 `id` 必须**各自唯一**（不同集合的 ID 空间相互独立）；
- `selections[].personId` 与 `exceptions[].personId` 必须引用 `persons` 中已存在的人物 ID；
- `rulings` 的每个键必须是**多位人物共有**的共享称呼，且值必须属于该称呼的候选人物；
- 人物的配色等界面派生字段不写入文件，导入时按人物列表顺序重新配色；
- 不保存匿名预览、敏感信息巡检结果与撤销栈（均可由保存内容重算）。

导入校验与恢复语义见「操作说明」第 14 条：校验失败时逐条给出字段路径且当前工作不变；校验通过后一次性替换当前工作，预览与巡检由引擎重算，复核确认按「区间 + 人物 ID + 实际代号」匹配保留，撤销栈清空，新增人物 / 区间不复用已有 ID。

## 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口（环境变量，`server.js` 读取）；`docker-compose.yml` 固定把宿主机 `3000` 映射到容器 `3000` |

## 目录结构

```
server.js            Express 静态服务 + /api/example 内置示例
example.json         内置示例数据（原稿 + 预置人物规则，含手机/邮箱/身份证示例）
public/anonymize.js  匿名化引擎（纯函数，浏览器/Node 共用）：匿名映射（含共享称呼裁决
                     adjudications）、称呼归属 aliasOwners、引文生成 buildCitation、
                     批量匹配、敏感信息识别 detectSensitive 与判级 classifyCandidates、
                     本地工作包构建 buildWorkPack 与校验 validateWorkPack（version=1）
public/app.js        前端交互（规则、框选、例外、撤销栈、敏感信息巡检、人工复核与交付、
                     工作包下载/导入与一次性恢复、渲染）
public/index.html    页面结构
```
